Install guide

From bare hardware to a bootable EFI

OCforge scans a machine, works out which macOS release its hardware can actually run, and assembles the OpenCore config.plist, kexts, and SSDTs to match. Two ways to get from there to an installed Mac — pick one below.

Path A

Regular build

The target machine has internet during install — the usual case. Build an EFI, boot the normal macOS installer or recovery, done.

Read the steps →

Path B

Offline installer

The target machine shouldn't or can't touch the internet mid-install — air-gapped, metered, or just unreliable Wi-Fi. Stage everything on a USB ahead of time instead.

Read the steps →
PATH A

The regular build

Three commands, run on any Linux, Windows, or macOS machine — it doesn't have to be the target machine itself, though it usually is.

1

Install the CLI

Needs Python 3.11+, no other runtime dependencies. Or skip this step entirely and use the desktop GUI instead, which offers to install this for you.

pipx install "git+https://github.com/kevinisgoated24-spec/OCforge.git"
2

Scan the machine

Reads the CPU, GPU, network cards, storage, and board — writes it all to a spec file so the next two steps don't need to re-detect anything.

ocforge probe --save my-pc.json
3

See what it'll build

Prints the macOS target it picked and why, the SMBIOS model, every kext and SSDT with a reason. Nothing is written to disk yet — this is the "check before you commit" step.

ocforge plan --spec my-pc.json
→ Want the full reasoning behind every config.plist line, with a Dortania link for each? Run ocforge explain --spec my-pc.json instead.
4

Build it

Either a plain EFI/ folder you copy onto the drive's EFI partition yourself —

ocforge build --spec my-pc.json --out ./EFI

— or straight onto a USB stick with the macOS recovery included. Run ocforge usb first to find the right disk name:

ocforge build --spec my-pc.json --usb /dev/sdX --recovery
! --usb erases the target disk. OCforge asks you to confirm before writing anything.
5

Boot it

Copy EFI/ onto the drive's EFI partition if you built to a folder, then boot from it. Three things to do before you trust it long-term:

Do thisWhy
Run ocforge validate --efi ./EFIConfirms OpenCore's own ocvalidate is happy with the config
Map your USB ports after first bootThe stock port map is a placeholder — real ports need mapping for USB 3 to behave
Set a real SMBIOS serialOnly needed if macserial wasn't available at build time — OCforge tells you when this applies
PATH B

The offline installer

For a target machine that shouldn't touch the internet mid-install. Downloads the full macOS installer and stages corpnewt/UnPlugged alongside your EFI — both large, and this needs your internet, once, on the machine running OCforge, not the target's.

1

Stage everything

Same spec file as the regular path. This step is slow — it's downloading Apple's full installer image.

ocforge offline-installer --spec my-pc.json --out ./offline-installer

What comes out the other side:

./offline-installer/EFI/ — your usual EFI, unchanged ./offline-installer/com.apple.recovery.boot/ — the boot environment ./offline-installer/ExFAT/InstallAssistant.pkg — the actual installer ./offline-installer/ExFAT/UnPlugged.command
2

Write the USB — two partitions

A FAT32 partition (~1 GB — holds EFI/ and com.apple.recovery.boot/) and an ExFAT partition (the rest — everything under ExFAT/).

Let OCforge partition and write both for you:

ocforge offline-installer --spec my-pc.json --usb /dev/sdX
! Destructive — asks to confirm first. Needs exfatprogs on Linux (sudo apt install exfatprogs); macOS and Windows format ExFAT natively.

Or format it yourself and copy the two folders over by hand if you'd rather not hand OCforge the disk.

3

Run UnPlugged from Recovery

Boot the USB on the target machine. UnPlugged is a bash script that needs diskutil/installer/asr — real macOS APIs nothing outside a booted Recovery environment has, so this part can't be automated from outside it.

cd /Volumes/ExFAT-VOLUME-NAME
./UnPlugged.command

It walks you through picking the target disk from there — the actual install happens fully offline after this point.

→ Targeting macOS Sonoma (14) or newer? The boot environment deliberately uses an older BaseSystem (Monterey) even though the install payload is the newer release — Recovery on 14+ can't mount FAT32/ExFAT itself otherwise. OCforge does this automatically and says so. Expected, not a bug.
AFTER EITHER PATH

Map your USB ports

Both paths above ship USBToolBox.kext — the driver — but not a map of your physical ports, which is specific to this exact board and has to be built once. Skip it and USB mostly works anyway; do it properly and every port reports the right speed and there's no 15-port ceiling surprise later.

1

Get the mapping app — on Windows

Not the kext you already have — a separate tool, USBToolBox/tool. Download Windows.zip from its releases and run Windows.exe — a terminal-style menu opens. Mapping happens on Windows, not macOS: only Windows can auto-detect USB2/USB3 companion port pairs and guess port types, and macOS 11.3+ has a broken XhciPortLimit that makes mapping from within macOS more painful. No Windows install handy? Boot a Hiren's BootCD PE USB and run the tool from its cmd (Shift+F10).

→ Under the hood, the Windows build uses USBToolBox/usbdump — an adapted Microsoft USBView — to enumerate the raw port data. You never run it directly; it's bundled into Windows.exe.
2

Discover every port

Press D for Discover Ports. Plug a device into one port at a time, wait for it to show up in the list, then unplug and move on — don't rush this.

Test each type properly:

Port typeWhat to do
USB 3 Type-AOne device is usually enough (companion detection works on Windows); use a USB2 and USB3 device if you want to be sure
USB-CPlug in, note it, unplug, flip the plug over, plug it back in — orientation can enumerate differently
Legacy USB 1.1 (old OHCI/UHCI boards)Plug in a mouse or keyboard — most modern USB2 devices skip straight past the 1.1 personality
Internal-only (headers, built-in webcam/BT)No device needed — just leave it typed correctly, you'll mark it internal below
→ Turn on Show Friendly Types and Add Comments to Map in settings before you start — friendly types make the list readable, and comments let you label ports ("rear blue USB3", "front header") for later.
3

Type your ports and mind the 15-port cap

Press S for Select Ports. For each detected port, set its real type and mark it internal or external. Apple caps every USB controller at 15 mapped ports — most modern boards physically expose more, so the tool will warn you if you're over. Disable ports you'll genuinely never use (an unwired header, a dead legacy port) rather than cutting the last N in the list at random — check what each one is actually wired to first.

4

Build the map

Press K to build. Pick the USBToolBox kext format — it pairs with the USBToolBox.kext driver you already have installed. (The alternative, AppleUSBHostMergeProperties, is a native-Apple-style injector if you'd rather not depend on the third-party driver.) Out comes UTBMap.kext — a real kext folder, generated for this board specifically — plus a Ports.txt summary worth keeping for reference.

5

Add it to your EFI

Copy the whole folder in:

EFI/OC/Kexts/UTBMap.kext

Then add a matching entry under Kernel → Add in config.plist — OCforge doesn't generate this one for you automatically, since it's tied to a map that doesn't exist until you've built it. The Editor tab's plist tree view (or ocforge plist show / save) is the quickest way: duplicate the existing USBToolBox.kext entry, change BundlePath to UTBMap.kext, leave everything else the same shape. Order matters — USBToolBox.kext must load before UTBMap.kext.

! If you have UTBDefault.kext installed (the placeholder that unlocks all ports before you had a real map), remove it and its Kernel → Add entry now — leaving both in can conflict with your new map.
6

Reboot and check

Every port you mapped should now show its correct type in About This Mac → System Report → USB, instead of the generic fallback behavior USBToolBox uses with no map at all — and the boot log shouldn't show any "no personality found" or over-the-limit warnings.

ALTERNATIVE

Prefer a GUI?

The desktop app wraps both paths above in the same six tabs either way: Detect → Plan → Config → Forge (this is where the offline-installer toggle lives) → Editor → Assistant. It offers to install Python + the CLI for you on first launch. Grab the build for your OS — Windows, macOS, or Linux — from the releases page.

→ Windows: if launching it fails with "The code execution cannot proceed because MSVCP140.dll was not found," install the Visual C++ Redistributable and try again.
